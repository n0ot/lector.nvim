1. Introduction                                      *lector-introduction*

lector.nvim is an independent producer of semantic editor information. It is
not a component of the Lector terminal screen reader. It sends the versioned
Lector application-accessibility protocol so Lector and other compatible
terminal screen readers can consume editor state without inferring it from
terminal cells and cursor motion.

The plugin does not define mappings or replace Neovim's visual UI. It yields
to ordinary terminal reading for transient output, nested terminal
applications, and terminal buffers.

==============================================================================
2. Setup                                                    *lector-setup*

Add n0ot/lector.nvim to 'runtimepath', then call: >lua

    require("lector").setup()
<
setup() returns false and remains inert when |nvim_ui_send()| is unavailable.
Calling setup() again replaces the previous configuration and autocmd group.
Reloading the Lua module first tears down the previous active instance, so
plugin updates can safely replace it within the same Neovim process.

To stop and remove listeners and commands programmatically: >lua

    require("lector").teardown()
<

3. Commands                                              *lector-commands*

                                                        *:LectorSay*
:LectorSay {text}
        Send {text} as application-authored semantic speech.

                                                     *:LectorStatus*
:LectorStatus
        Read the current buffer name, state, cursor location, fold state, and
        active Visual selection. No default mapping is installed.

                                    *:LectorCompletionDocumentation*
:LectorCompletionDocumentation
        Read documentation for the currently selected completion item when
        the provider exposes it.

                                             *:LectorDiagnostic*
:LectorDiagnostic
        Read the diagnostic containing the cursor. When the cursor is outside
        every diagnostic range, read the most severe diagnostic on the current
        line. Source, code, and the number of additional line diagnostics are
        included when available. Cursor position is intentionally omitted. No
        default mapping is installed. The Lua equivalent is: >lua

            require("lector").announce_current_diagnostic()
<

                                *:LectorAccessibilityEnable*
:LectorAccessibilityEnable
        Enable lector.nvim and reassert semantic policy.

                               *:LectorAccessibilityDisable*
:LectorAccessibilityDisable
        Send protocol end, close semantic menus, and disable lector.nvim.

Use |:checkhealth| lector to inspect compatibility and current state.

4. Options                                                *lector-options*

Every option below defaults to true and is passed to setup():

announce_buffers
        Announce the buffer name on entry. Cursor-line reading remains a
        separate cursor-motion behavior.

announce_cursor
        Announce cursor destinations from the resulting editor geometry. A
        provider-declared navigation that has no distinct destination
        announces either "no previous item" or "no next item". Entering
        characterwise Visual mode announces the mode without repeating the
        character at the cursor.

announce_deletions
        Announce where the cursor lands after Insert deletions and structured
        edits. Linewise, blockwise, and Visual metadata is taken from Neovim;
        other destinations are inferred from the resulting edit geometry. A
        characterwise Visual deletion reads its resulting character. Deleted
        contents are not spoken.

announce_diagnostics
        Announce changed diagnostics when entering or revisiting a diagnosed
        line. Normal-mode movement into a different diagnostic range announces
        that diagnostic after the cursor destination. Identical events and
        movement within the same diagnostic are coalesced.

announce_modes
        Announce meaningful editor mode changes.

announce_messages
        Announce recorded messages and yield transient output to ordinary
        terminal reading.

announce_floating_windows
        Announce unclaimed non-focused floating windows after their title and
        contents stabilize. This includes custom Lua and which-key windows.
        Provider windows already owned by a semantic adapter, such as Blink
        completion, are not repeated.

announce_command_line
        Announce command-line type, movement, history, and completion.

announce_value_changes
        Announce numeric values changed by normal-mode text operations.

announce_puts
        Announce put text or a concise line/block summary.

announce_folds
        Announce closed-fold entry and fold opening or closing.

announce_search
        Announce current and total search matches plus wrapping.

announce_quickfix
        Announce structured quickfix and location-list destinations, including
        list title, entry type and text, file, line, column, and list position
        when available.

announce_recording
        Announce macro recording start and stop.

announce_spelling
        Announce misspelled, rare, regional, and capitalization results, plus
        the numbered suggestions shown by the native |z=| interface. The
        visual interface is not replaced.

announce_completions
        Announce native and registered completion menu selection.

announce_popup_menus
        Announce Neovim's native right-click context menu.

completion_include_kind
completion_include_source
completion_include_position
        Include the corresponding metadata in completion announcements.

5. Behavior                                              *lector-behavior*

Cursor semantics are derived from Neovim events and before-and-after editor
geometry. Mappings, Lua callbacks, and programmatic cursor changes use the
same path. Provider-declared navigation can additionally report that no
previous or next item exists; see |lector-provider-navigation|.

Operator edit destinations use |TextYankPost|, including its Visual and
register-type metadata. Put announcements use |TextPutPost| when available and
a change-verified edit fallback otherwise. |vim.on_key()| captures only the
state before an input is processed; literal normal-mode keys and mapping
expansions do not determine cursor or edit semantics. A small native-output
recognizer observes resolved input only to prepare interfaces which draw
before a useful event is available. Fold, search, quickfix, recording,
spelling, diagnostic, command-line, message, and window state come from
documented Neovim APIs and events.

A command line which remains open beyond its input transaction is announced
as interactive editor state. One which enters and leaves within the same
transaction is treated as an implementation detail. Opaque Lua mapping
callbacks temporarily allow automatic output reading while keeping cursor
tracking suppressed. Semantic policy resumes when the callback returns, or
remains yielded if Neovim stops at a pager or hit-enter prompt.

Window and menu closure is silent. When a close moves focus to another editor
context, the destination is announced through the ordinary window- or
buffer-entry semantics instead of describing the implementation-level close.

Actions which may display output yield to ordinary terminal reading before
Neovim processes the action. Visible output is not repeated as synthetic
speech. A resulting semantic event immediately reclaims policy. Output-only
interfaces such as pagers and hit-enter prompts enable automatic reading but
keep cursor tracking suppressed because their terminal cursor is a rendering
detail. Visual presentation is not reconstructed or removed.

The native |z=| spelling interface is the exception: its visible list remains
unchanged, and the same suggestions are obtained from |spellsuggest()| and
announced semantically before the interface opens. This avoids depending on a
terminal redraw heuristic for a blocking prompt. If `announce_spelling` is
disabled, |z=| uses the ordinary transient-output handoff instead.

Lector owns predictable editor contexts: Normal, operator-pending, Insert,
Replace, Visual, Select, and semantic command-line editing. A focused floating
UI, a prompt buffer, a terminal job, an external command, or an unknown future
mode instead receives the screen reader's complete ordinary policy, including
cursor tracking. Policy is reclaimed when focus returns to an owned editor
context. Newly displayed, non-focused floating windows are tracked by window
identity and content. Unclaimed windows are announced semantically after their
title and buffer text stabilize; later content changes are deduplicated and
announced once. Windows claimed by another semantic adapter are skipped.

Native Normal- and Visual-mode commands which directly render output are
recognized before that output appears. These include |[i|, |[I|, |[d|, |[D|
and their `]` counterparts, |g<|, |g]|, character information, tag selection,
and keyword lookup. |z=| is recognized through the same mapping-safe input
path but announces its suggestions semantically. Entering Visual mode and
ordinary editor navigation never enable automatic reading.

The plugin reasserts its complete policy after resume, focus gain, UI entry,
and relevant shell return. It sends end before suspend, exit, and terminal
buffer entry. The terminal consumer remains responsible for reset,
alternate-screen, PTY, and pane-local failsafes.

While |vim.ui.select()| or |vim.ui.input()| is active, lector.nvim sends
protocol end so the terminal screen reader can read the provider's ordinary
visual interface. Semantic policy is restored when the interaction finishes.
This includes default and third-party providers, LSP code actions, and other
multi-choice or input workflows. A selector whose options identify
`kind = "spell"` is claimed semantically when |announce_spelling| is enabled,
so Neovim 0.13's |z=| implementation does not cause a duplicate handoff.

6. Provider APIs                                    *lector-provider-api*

                                                   *lector-provider-navigation*
Navigation providers can declare direction without exposing their mappings or
text-object names: >lua

    require("lector").observe_navigation("next", function()
      provider.goto_next_item()
    end)
<
Use "previous" or "next". lector.nvim preserves the callback's return values
and errors. If it produces no cursor, buffer, text, or semantic speech change,
lector.nvim announces "no previous item" or "no next item" after Neovim has
finished processing related events.

                                                       *lector-provider-search*
Providers that repeat a search can similarly expose the operation rather than
its mapping: >lua

    require("lector").observe_search(function()
      provider.goto_next_match()
    end)
<
Successful searches use Neovim's search state for position and wrap
announcements.

                                                      *lector-completion-api*

Plugins may publish provider-neutral menu state: >lua

    require("lector").update_menu({
      id = "provider-menu",
      name = "completion menu",
      count = 3,
      index = 2,
      label = "print",
      kind = "function",
      source = "LSP",
      documentation = "Print a value.",
    })

    require("lector").close_menu("provider-menu")
<
index is one-based and may be omitted to represent no selection. label is
required for a selected item. kind, source, and documentation are optional.

==============================================================================
7. Compatibility                                  *lector-compatibility*

The terminal transport requires Neovim 0.12 or newer, API level 14, and
|nvim_ui_send()|. Individual newer events such as TextPutPost and SearchWrapped
are feature-detected and have bounded fallbacks.

The protocol is one-way. checkhealth can validate the producer but cannot ask
whether the host terminal consumed a message.

Protocol specification: https://github.com/n0ot/lector.nvim/blob/master/PROTOCOL.md
Lector screen reader: https://github.com/n0ot/lector
